# check_firewall_rules.py

## Description
Monitor the number of active nftables tables/chains/rules (or, as a fallback, UCI-configured firewall zones/forwardings/rules/redirects) on NethSecurity 8.8 (OpenWrt, `fw4`/nftables-based firewall).

## Features
- Precise, structured rule counting via `nft -j list ruleset` (JSON output) - counts every real `rule`/`chain`/`table` object, including nftables statements that don't map to a simple keyword (e.g. `ct state vmap { ... }` dispatch rules generated by `fw4`)
- Falls back to `nethsec.utils.get_all_by_type()` (UCI-level zone/forwarding/rule/redirect counts) if `nft` is unavailable

## States
- **OK (0)**: Firewall data was read successfully via either source
- **UNKNOWN (3)**: Neither `nft` nor UCI firewall data could be read

## Output CheckMK
### Via nft (primary)
```
0 Firewall.Rules - OK - 3 tables, 40 chains, 97 rules (nft) | tables=3 chains=40 rules=97
```

### Via UCI (fallback, if nft is unavailable)
```
0 Firewall.Rules - OK - 2 zones, 1 forwarding, 4 rules (UCI) | zones=2 forwardings=1 rules=4
```

## Performance Data
- Via nft: `tables`, `chains`, `rules`
- Via UCI: `zones`, `forwardings`, `rules` (redirects are counted but not currently included in perfdata)

## Requirements
- `nft` (nftables) binary, for the primary/precise method
- Python 3 with `euci`/`nethsec` (`python3-nethsec`), for the UCI fallback

## Installation

```bash
cp check_firewall_rules.py /usr/lib/check_mk_agent/local/check_firewall_rules
chmod +x /usr/lib/check_mk_agent/local/check_firewall_rules
```

## Manual testing
```bash
python3 /opt/checkmk-tools/script-check-nsec8/full/check_firewall_rules.py
```

## Notes
- `nft -j list ruleset` is preferred over text-scraping `nft list ruleset` because nftables rule syntax is too varied to reliably classify by keyword prefix (e.g. `ct helper` object definitions, `ct state vmap {...}` dispatch rules, and ordinary accept/drop rules all share overlapping syntax) - the JSON output gives an unambiguous, typed rule count instead
