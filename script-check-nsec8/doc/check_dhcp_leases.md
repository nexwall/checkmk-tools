# check_dhcp_leases.py

## Description
Monitor DHCP pool usage on NethSecurity 8.8, checking the number of active leases against the aggregate configured pool capacity. Supports multiple DHCP pools (not just `lan`).

## Features
- Enumerate configured DHCP pools via `nethsec.utils.get_all_by_type(uci, 'dhcp', 'dhcp')` (skips pools with `ignore=1` or `dhcpv4=disabled`)
- Read the lease file (resolved via UCI `dhcp.ns_dnsmasq.leasefile`, falling back to `/mnt/data/dnsmasq/dhcp.leases` or `/tmp/dhcp.leases`)
- Count active (unexpired) vs expired leases by comparing timestamps
- Calculate aggregate usage percentage across all active pools
- Threshold: WARNING 80%, CRITICAL 90%

## States
- **OK (0)**: Usage < 80%, or no active DHCP pool configured (nothing to alert on)
- **WARNING (1)**: Usage >= 80%
- **CRITICAL (2)**: Usage >= 90%

## Output CheckMK
```
0 DHCP.Leases active=45;120;135;0;150 Leases active: 45/150 (30%) - OK (2 pool(s)) | active=45 expired=5 total=50 max=150 percent=30 pools=2
```

## Performance Data
- `active`: Active (unexpired) leases, with WARNING/CRITICAL thresholds embedded
- `expired`: Expired leases still present in the lease file
- `total`: Total lease file entries (active + expired)
- `max`: Aggregate DHCP pool capacity across all active pools
- `percent`: Usage percentage (active / max)
- `pools`: Number of active (non-ignored, non-disabled) DHCP pools counted

## Requirements
- Python 3 with `euci`/`nethsec` (`python3-nethsec`)
- Lease file generated by dnsmasq (`/tmp/dhcp.leases` or the UCI-configured `leasefile` path)

## Installation

```

```

## dhcp.leases file format
```
1732723456 aa:bb:cc:dd:ee:ff 192.168.1.100 hostname client-id
```
- Field 1: Unix expiration timestamp
- Field 2: MAC address
- Field 3: IP assigned
- Field 4: Hostname
- Field 5: Client ID

## Notes
- Pool full may prevent new device connections
- Static leases do not appear in this file
- Reduce lease time if small pool and many temporary devices
- If no pools are enabled (all `ignore=1` or `dhcpv4=disabled`), the check reports OK with "No active DHCP pool found" rather than alerting - this is a valid, common configuration, not a failure
